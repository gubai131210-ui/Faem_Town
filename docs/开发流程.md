# 开发流程

每一轮都按下面的顺序做完。顺序是：读文档、改代码、审核、运行、看画面、记下来、再报告。

没走完就说做完，这轮不算完成。命令、路径、环境在 `AGENTS.md`，这里不重复。

一轮只做进度里的下一项。设计文档和后续计划没写的作物、居民、系统不加。数值是第一版的，用户试玩之前不改。

## 1. 开工

读这些，只读和这一轮有关的章节：

1. `docs/进度.md`：做到哪、下一步是什么、已知问题里哪些还不能动。
2. `docs/架构.md`：新代码放哪、界面和数据怎么接。
3. `docs/设计文档.md`：这一轮要做的玩法。
4. `docs/决策记录.md`：已经定过的事照做。
5. `docs/后续计划.md`：计划之外的内容不做。

动手之前用一两句写下这一轮做完是什么样。和进度对不上就先停，问用户。

做完的标准：能指出进度里的下一项，以及这一轮不做什么。

## 2. 改代码

- 新的逻辑配单元测试。修 bug 先写一条现在会失败的测试，看到它失败，再改代码。
- 数据和规则放在已有的表和 autoload 里，按架构接。要换一种做法，先在决策记录里写原因。
- 数据表里用过的 `id` 不改名。
- 注释和给玩家看的字用中文。
- 用脚本改已有文件时，先写临时文件，再替换原文件（Python 用 `os.replace`）。
- 改 `project.godot` 之前确认 Godot 编辑器没开着这个项目。
- 新的 `class_name`、新的 `.dialogue` 标题，要先导入资源，测试才看得见。导入命令在 `AGENTS.md`。

做完的标准：改动在仓库里，对应的测试也在，而且测试说的是这一轮的行为。

## 3. 审核

跑测试之前先看一遍改动。长流程要好几分钟，审核没过就跑，是在等一个本来会失败的结果。

逐项看过才算审完：

- 和架构一致。偏离的地方，决策记录里已经有原因。
- 没有推翻已有决策，没有改用过的 `id`。
- 范围停在这一轮。没有顺手加内容、改数值、改别的系统。
- 新逻辑有测试；修 bug 的测试在改代码之前会失败。
- 界面走 `UiKit`，提示走 `EventBus.banner_requested`，不在屏幕中间另画一块字。
- 玩家存档不会被测试或截图脚本写到。截图和流程用它们自己的存档目录。

做完的标准：上面每一项都有结论。有一项过不了，先改代码，再重新审。

## 4. 运行

在 `farm-town/` 下跑，一次只开一个 Godot。上一个还在，就等它结束或先停掉。命令在 `AGENTS.md`。

按这个顺序，前一步没过就不跑下一步：

1. 只跑这一轮的测试脚本。`-gselect` 是脚本名的前缀，一次一个，不写成逗号列表。
2. 跑全部单元测试。
3. 改动进了游戏里能走到的路径，就跑无头自动流程。输出里要看到 `FLOW PASS`。`CHECK FAILED`、解析错误、脚本错误都是没过。无头流程可能很久才打印这一行，时长以 `tests/flow/flow.gd` 里的 `TIMEOUT` 为准。

这些坑会让一次本来对的运行看起来像失败：

- `flow.gd` 的 `_run` 是一个函数。循环变量在整段里共用，同名会直接解析失败。
- 对话标题要导入之后才进 Dialogue Manager。没导入就报找不到标题。
- 新游戏开局，物品栏第一格是锄头。测试往背包里放东西之前先看清选中的是哪一格。
- 停掉的 Godot 退出码会是 4294967295。那是进程被结束，不是测试结果。

做完的标准：全部单元测试通过；该跑的无头流程输出 `FLOW PASS`。数字记下来，报告和进度日志用同一组。

## 5. 看画面

这一轮改了玩家能看见的东西，就看图。没看图，不说效果怎样。

- 代码画的素材：用 `dump_art.gd` 导出预览，打开图看。
- 游戏里的界面和场景：无头流程全过之后，再看截图。完整的带窗口流程会弹出游戏窗口，一轮最多一两次，开之前先告诉用户。中途报错的话窗口不会自己关，告诉用户去关。
- 只需要一张画面时，写一个临时脚本截完就退出，然后删掉脚本。脚本要挂在场景树的根上，换场景才不会把它卸掉。存档目录用流程那一套，不写玩家的档。
- 截图在 `farm-town/_preview/`，不提交。
- 打开图片，写出画面上实际有什么：字在哪、挡没挡住、颜色和形状能不能认出来。

动作、手感、声音判断不了。报告里写明要用户试玩，不说“流畅”或“好听”。

做完的标准：看得见的改动有一张对应的图，而且你看过，能说出图上的内容。这一轮改的形状、颜色、是谁、什么天气要在图上认出来；认不出来就改，再截，直到认出来。纯逻辑、纯数据、没有画面变化的一轮，写明没有截图、为什么。

## 6. 记下来

- `docs/进度.md`：阶段那一句、里程碑那一行、这一批的清单、日志。日志写测试通过了多少、流程过了多少项、图上看到了什么、哪些要用户试玩、提交了没有。
- 这一轮定了以后还要遵守的做法：在 `docs/决策记录.md` 加下一条，编号接着最后一条。
- 代码的位置或接法变了：改 `docs/架构.md` 对应的那一行。

做完的标准：进度日志和这次运行的数字一致。有选择就有决策记录。

## 7. 报告

用中文说明：做了什么、测试和流程的结果、图上看到了什么、哪些要用户试玩。

用户没要求，就不提交、不推送。

做完的标准：报告里的每项都能在仓库、测试输出或截图里对上。
