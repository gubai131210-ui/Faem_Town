# 架构

> 这份文档规定代码怎么组织。写新功能前先看这里；要偏离时，先在 [决策记录](决策记录.md) 里写明原因。
> 玩法内容见 [设计文档](设计文档.md)，进度见 [进度](进度.md)。

## 1. 技术栈

| 项 | 选择 |
|---|---|
| 引擎 | Godot 4.7.2，GL Compatibility 渲染 |
| 语言 | GDScript，全部写静态类型 |
| 画面 | 基础分辨率 384×216，整数倍放大，纹理不过滤 |
| 角色美术 | Blender 5.3 脚本建模和渲染，输出像素序列帧 |
| 大件物件 | Blender 出形体，脚本补像素纹理和描边（房子、室内、家具、栅栏） |
| 其他美术 | 代码逐像素绘制（树、作物、图标、地面、界面） |
| 测试 | GUT |
| 对话 | Dialogue Manager |

## 2. 核心原则

1. **状态和画面分开。** 游戏状态（田里种了什么、背包里有什么、今天第几天）放在纯数据对象里，不依赖任何节点。节点只负责把状态画出来和接收输入。这样玩家不在农场时作物照样生长，存档就是把状态对象写出去。
2. **内容放在数据表里。** 加一种作物、一条鱼、一个居民，只改 `data/` 下的表，不改代码。
3. **向下调用，向上发信号。** 父节点可以直接调子节点的方法；子节点不调父节点，只发信号。
4. **功能之间不直接引用。** 钓鱼不 `preload` 种田的脚本。需要联动时走全局系统或 `EventBus`。
5. **全局单例要少。** 只有“全局唯一、跨场景存在、自己管理自己数据”的系统才做成 autoload；纯工具函数用 `class_name` 加静态方法。
6. **第三方代码只放 `addons/`。** 不改插件源码；要定制就在自己的目录里包一层。

## 3. 目录结构



```
farm-town/
  addons/              第三方插件，不改动
  core/                全局系统（autoload）和基础工具，不含具体玩法
  data/                内容表：作物、鱼、物品、居民、节气……
  dialogue/            对话文件，每个居民一个
  features/            每个玩法一个目录，脚本、场景、专属素材放在一起
    player/
    farming/
    economy/           出货箱、商店
    fishing/
    animals/
    crafting/          加工设备、烹饪
    mine/
    npc/
    lamps/             灯、供品、主线进度
    story/             终幕和结局的规则
    festival/          六个节日的规则
    ui/
  maps/                每个区域一个场景
  art/                 生成出来的图片（Blender 输出等）
  art_gen/             代码画图的脚本（树、作物、图标、界面），以及读取 Blender 物件的 PropArt
  game/                游戏主场景：把地图、玩家、镜头、界面接到一起
  tests/               GUT 测试
  tools/               Blender 脚本和预览导出等编辑期工具，带 .gdignore
docs/                  文档（在 Godot 项目目录之外）
```

规则：

- 文件和目录一律 `snake_case`，节点名 `PascalCase`。
- 素材跟着用它的功能走；多个功能共用的才放 `art/`。
- `features/a/` 不引用 `features/b/` 里的文件。

## 4. 分层

```
maps / features/ui      场景和界面：组装节点，显示状态，接收输入
        ↓ 调用
features/*              玩法逻辑：每个玩法自己的状态对象和规则
        ↓ 调用
core                    全局系统：时间、天气、存档、数据库、事件
        ↓ 调用
data / addons           内容表和第三方库
```

下层不知道上层的存在。上层要知道下层发生了什么，就连接下层的信号。

## 5. 全局系统

autoload，按加载顺序：

| 名称 | 位置 | 职责 |
|---|---|---|
| `Database` | `core/` | 启动时读入并校验 `data/` 下所有表，提供按 id 查询 |
| `EventBus` | `core/` | 跨功能的全局信号，数量要少，每个都写注释 |
| `SaveSystem` | `core/` | 存读档，调度各系统的存取 |
| `GameClock` | `core/` | 时间、日期、季节、节气；每日结算的固定顺序 |
| `GameState` | `core/` | 玩家的全局数据：背包（每格带品质）、金钱、体力、生命（不进存档）、工具等级、剧情标记 |
| `SceneRouter` | `core/` | 主菜单与游戏、区域之间的切换和转场 |
| `Audio` | `core/` | 音效和音乐；退出游戏一律走 `Audio.quit_game(code)`，先停声音再退（决策 049） |
| `DialogueManager` | `addons/` | 对话运行时（插件提供） |
| `Weather` | `core/` | 今天和明天的天气 |
| `Farming` | `features/farming/` | 农场耕地（`FarmState`）和果树（`Orchard`）的状态、存档、每日生长 |
| `Shipping` | `features/economy/` | 出货箱和每日结账 |
| `Foraging` | `features/foraging/` | 各张地图上的野外采集物：每天攒几份，地图载入时落到空地上 |
| `Fishing` | `features/fishing/` | 哪片水现在有什么鱼、等多久咬钩、钓到的记录；收放线的规则在同目录的 `FishFight` |
| `Animals` | `features/animals/` | 农场上订了、盖好了哪些建筑，养着哪些动物，心情、喂食、产物和每日结算；动物在地图上的节点是同目录的 `Critter`（决策 045）；家里的猫或狗、蜜蜂和蚕也记在这里（决策 046、048） |
| `Crafting` | `features/crafting/` | 买了哪些加工设备、每台里正在做什么、还要几天；会哪些菜、做菜、云娘每天教一道（决策 047） |
| `Mine` | `features/mine/` | 沉灯井：最深到过哪层、亮着的井灯、现在在第几层、这一趟得来的东西（晕倒丢一半）；一层的样子是同目录的 `MineFloor`（纯数据，每次下来重新生成，不进存档），里面的忘形是 `MineMonster`（也是纯数据），连段计数是 `Combo`（决策 050、051）；忘形绕石头找路（`next_step`、`clear_line`）和互相推开（`separate`）也在 `MineFloor` 里（决策 052）；首领是 `MineMonster` 的子类 `MineCart`、`MineCatfish`，飞着的纸钱和水弹是 `MineShot`，打倒过的首领和欠着的掉落记在 `Mine.bosses`、`Mine.owed`（决策 053） |
| `Lamps` | `features/lamps/` | 每盏灯供了什么、亮没亮；点亮时发 `EventBus.lamp_lit` |
| `Quests` | `features/npc/` | 公告栏委托：贴着的、接了的、交过的；交付只算报酬，加熟悉度由 `Residents` 做 |
| `Residents` | `features/npc/` | 居民的全局状态：见过谁、今天说过几次话、熟悉度、忆等级、送礼和已知的喜好；也是对话文件查询游戏状态的入口 |

玩法自己的全局状态（`Farming`、`Shipping`、`Foraging`、`Fishing`、`Animals`、`Crafting`、`Mine`、`Lamps`、`Quests`、`Residents`）也做成 autoload，放在各自的功能目录里：玩家不在场时它们也要参加每日结算和存档。

约定：

- autoload 之间只能依赖排在自己前面的。
- autoload 不持有任何场景里的节点引用。

### 每日结算

睡觉时 `GameClock` 推进一天。各系统用 `GameClock.register_daily(顺序, 回调)` 登记自己的结算步骤，按固定顺序执行：天气 → 作物和果树 → 采集物 → 动物 → 加工设备 → 居民日程 → 出货结账，全部跑完再发出 `day_started`，然后自动存档。顺序由 `GameClock` 里的 `ORDER_` 常量决定，不靠信号连接的先后。

每日结算时玩家在屋里，户外地图没有载入。结算要用到地形的地方（水渠是否挨着水、采集物落在哪块空地）有两种做法：事先把结果存进状态里，或者只记数量、等地图载入时再落地。不要在结算里去找地图节点。

## 6. 数据表

- 格式是 JSON，放在 `data/`，一类内容一个文件，例如 `data/crops.json`。
- 每条内容有一个 `id`：小写英文加下划线，例如 `white_radish`。**id 一旦进入存档就不能改名。** 显示名用中文，放在 `name` 字段。
- `Database` 读入时把每条数据转成带类型的定义对象（`CropDef`、`ItemDef`……），代码里不直接摸字典。
- 表之间的引用（作物的种子 id、居民喜欢的物品 id）在启动时校验，测试里也校验一遍。错了直接报错，不带病运行。

选 JSON 而不是 Godot 的 `.tres`，是因为内容量大、多数由脚本和 AI 批量生成，纯文本表更容易批量写、对比和检查。

## 7. 存档

- 位置 `user://saves/slot_N.json`，三个档位。
- 每个有状态的系统实现两个方法：`save_data() -> Dictionary` 和 `load_data(data: Dictionary) -> void`。`SaveSystem` 只负责收集、写盘和分发。
- 存档带 `version` 字段。结构变化时加一个迁移函数，把旧版本逐级升到新版本。
- 写盘先写临时文件，成功后再替换，并保留上一份作备份。读档失败时不覆盖原文件。
- 只在睡觉时自动存档，所以不需要保存“一天中途”的状态。

## 8. 场景与节点

- 可复用的东西做成独立场景（`.tscn`），根节点挂一个同名脚本。
- 界面目前全部用代码搭（`features/ui/`，外观统一从 `UiKit` 取）；农场、农舍、镇广场、南溪的地图也是代码摆的。
- 新的弹窗照这个样子搭（决策 056）：主面板用 `UiKit.window()`（先建它、再往里加东西），标题放在顶上的标题带里（y 5、8 像素字），内容从 y 20 左右开始、四周留 8 像素；选中的行用 `UiKit.row_back()`；按键提示用 `KeyHints`；`open()` 里显示以后调一次 `UiKit.pop(面板)`。不要再自己拼底色和边框。
- 给玩家的一句话提示一律发 `EventBus.banner_requested`，由 `Hud` 在左上角出提示条；不要自己在屏幕中间放大字。需要长一点的说明就在文字里换行，换行后面的会用小一号的字。屏幕左上角留给提示条，别的常驻界面不要放那里。
- 室外地图继承 `maps/outdoor_map.gd`（`OutdoorMap`）：地形表、地面贴图、撒树和草、水面、夜灯、居民的出现和走动都在里面，子类只写布局和交互（决策 025）。采集物的显示和拾取（`_sync_forage` / `_pick_forage`）、蟹笼的放和收（`_trap_query` / `_trap_perform` / `_sync_traps`）也在基类里，凡是有水有草的地图都能用（决策 043）。被灯挡着的路用 `_add_fog_bank` 摆一团雾、灯亮时 `_fade_fog` 散掉；采集表里 `beach` 为真的东西只长在沙滩上，地图调 `Foraging.settle(map_id, 沙地格子, [], true)`（决策 058）。
- 居民是 `features/npc/npc.gd`（`Npc`）节点，只管站、走、坐、画；去哪儿由地图按 `NpcSchedule` 算出来的日程决定（决策 026）。地图通过回调告诉它玩家在哪、哪格被人占着（`player_position`、`occupied`），它用信号 `arrived`、`stuck` 向地图要路；居民之间的闲聊由地图撮合（`OutdoorMap._start_chats`，决策 035）。以后手工摆放的地图可以改用场景文件。
- 玩家 `features/player/player.gd` 有四个状态：自由、做动作（锄地、浇水、甩竿、挥武器等带时间表的动作）、保持姿势（`hold` / `release`，持竿等鱼）、翻滚（`roll`，这期间 `invincible()` 为真）。一次钓鱼从甩竿到收竿由 `game/fishing_session.gd` 串起来：它要同时碰玩家、地图和 `Fishing` 的规则，所以放在 `game/`（决策 040）。地图用 `fishing_water(tile)` 说哪一格是哪片水。
- 地图基类 `GameMap` 有两个剧情钩子：`entered()` 在地图载入、玩家放好以后由 `Game` 调一次（序幕在这里起）；`cutscene` 为真时 `Game` 不收玩家输入、`OutdoorMap` 不动居民日程和闲聊（决策 039）。钓鱼相关的两个：`sunken_relic(tile)` 说这一格水底沉着哪件遗物（默认没有），`relic_fished(id)` 在钓起遗物收竿后回调（决策 044）。
- 农场上的建筑和动物由农场地图画：`Animals.changed` 一响就对一遍（`_sync_ranch`），每过一分钟看一眼动物该不该在外面（`_sync_critters`）。建筑的位置、占地、院子都在 `BuildingDef` 里；`OutdoorMap._no_scatter(tile)` 让子类留出不撒野树石头的空地（决策 045）。
- 农场地图还画这几样，都是“状态变了就对一遍”：加工设备（`Crafting.changed` → `_sync_machines`，位置在 `MachineDef.tile`）、稻草人（`Farming.scarecrows_changed` → `_sync_scarecrows`）、早上的乌鸦（`_spawn_crows`，读 `Farming.raided`）、家里的猫狗（`_sync_pet`）。牵着牛犁地是地图的两个接口 `plow_row(tile, facing)` 和 `plowed()`，`Game` 在锄地前问一句（决策 046–048）。
- 两个功能之间要传话、又不能互相引用时，由 `game/` 里的小工具牵线：`game/ranch_link.gd`（`RanchLink`）替 `Animals` 去 `Farming` 查蜂场周围开着什么花。
- 主角的动作名和姿势在 `Player.ACTION_ANIMS`：除了锄、浇、种、收、甩竿，还有 `tend`（喂、摸、收蛋、往设备里放东西）和 `place`（立稻草人），都用 `reach` 的姿势。地图的 `query_use` 返回动作名，`interact` 表示不做动作直接生效。面前同时有几样东西时归谁，`query_use` 和 `perform` 的顺序要一致，农场上的顺序见决策 049。
- 居民换日程：`NpcDef.early_until` 写一个标记名，标记没立起来时用 `early_schedule` / `early_rain_schedule`（阿牧在牧野灯亮前）。食物效果的剩余时间由 `GameState.buff_text()` 给，变化时发 `buff_changed`，`Hud` 画在时钟下面。
- 矿井的一层是 `maps/mine/mine_map.gd`：直接继承 `GameMap`（不是室外地图），按 `Mine.current` 画地面、石头、梯子、井灯；下一层就是 `Mine.descend()` 以后再 `SceneRouter.travel(&"mine", ...)` 重新载入同一张地图。主角的动作名多一个 `mine`（用锄头的姿势）。井里是唯一 `combat` 为真的地图：拿着武器 `query_use` 返回 `attack`，`Game` 管连段、蓄力和翻滚的按键，挥到的那一帧调地图的 `weapon_hit(weapon, step, skill)`；忘形每帧由地图的 `tick` 推着走，画它们的是 `maps/mine/monster_view.gd`（决策 051）。忘形出的事（落地、撞墙、吐水）记在它的 `events` 里、扔出来的东西记在 `pending_shots` 里，地图每帧取走配上声音特效；首领的血条、主角蹚水变慢（`Player.slow`）也由这张地图管。钓鱼和地图之间多了四个钩子（`GameMap.fishing_started / fishing_ended / fishing_bite / fish_landed`），默认什么都不做，矿井用它们把老鲶钓上岸（决策 053）。
- 地图：农场 `farm`、农舍 `farmhouse`、镇广场 `town`、南溪 `nanxi`、河岸 `riverbank`、东滩 `dongtan`、北坡牧场 `pasture`、山祠 `shanci`、井口 `wellhead`、矿井 `mine`，都登记在 `SceneRouter.MAPS`；地图之间靠 `trigger_at(tile)`（走到边上）或地图自己调 `SceneRouter.travel`（南溪和河岸之间的船）切换，`spawn_position / spawn_facing` 按出生点名字放人。
- 岚不是居民（不在 `data/npcs.json`，不归 `Residents` 管）：她是牧场和山祠两张地图自己放的一个精灵（`_sync_lan()`，每帧按天气和标记决定在不在），搭话由地图直接发 `dialogue_requested`，对话在 `dialogue/lan.dialogue`（决策 059）。
- 终幕和结局的规则在 `features/story/story.gd`（`Story`，只有静态函数，不是 autoload）：选了哪个结局记在 `GameState` 的标记里（`ending_keep / ending_clear / ending_name`）。对话文件通过 `Residents.ending_is / fog_lifted / all_remembered / choose_ending` 来问和选；选完发 `EventBus.ending_requested`，`Game` 等这段对话说完以后播结局（`_play_ending`）：`EndingScreen`（`features/ui/ending_screen.gd`，在对话框底下一层）铺画，对话框念 `dialogue/ending.dialogue` 的 `end_<结局>`，然后和睡觉一样过到第二天。灯亮以后居民头一回搭话走各自对话文件里的 `ending_news`（`Residents.title_for`），地图要变的地方直接问 `Story`（决策 060）。
- 井深的限制在 `Mine`：`deep_closed()` / `ladder_fogged()`，山祠灯没亮时 `descend()` 在第 30 层不往下；`enter()` 和升降机不拦（决策 059）。
- 节点引用用 `@onready` 和 `%唯一名`，不在 `_process` 里查找节点。
- 行为复杂的对象用状态机。玩家和井里的忘形都是枚举加 `match` 的简单状态机，没有引入库（决策 051）。
- 节日的规则在 `features/festival/festivals.gd`（`Festivals`，只有静态函数，不是 autoload），内容在 `data/festivals.json`（`FestivalDef`）。哪天是节日问 `Database.festival_on(day)`（`Weather` 靠它让节日那天只出晴和多云）。节日开着的时候 `NpcSchedule.spot_at` 先问 `Festivals.spot`，所有居民被排到场上；`OutdoorMap._door` 在居民没有这张地图的进出口时用节日表里的 `gate`。搭话走 `Residents.title_for` → `Festivals.passage`，话都在 `dialogue/festival.dialogue`（`fest_<节日>_host`、`fest_<节日>_<居民>`）；对话里做节日上的事一律 `do Residents.festival_act("<事>")`，由 `Festivals.act` 改状态、返回接着播哪一段，要念的数放在 `Festivals.said`、对话里用 `Residents.fest("<键>")` 取。做没做过记成标记 `fest_<事>_y<第几年>`。场上的摆设由地图自己放：镇广场的摊子、长桌、灯笼杆在 `town.gd` 的 `_place_festival`，南溪的河灯和萤火虫在 `nanxi.gd` 的 `_sync_festival`（决策 061）。

## 9. 美术管线

| 内容 | 来源 | 输出 |
|---|---|---|

## 10. 对话与剧情

- 每个居民一个 `dialogue/<id>.dialogue` 文件，必有 `first`、`work`、`daily`、`again` 四段（决策 028）；有忆的加 `memory_<级>`，有委托的加 `quest_<委托id>`；多人共用的叙述段放 `dialogue/common.dialogue`；六个节日上所有人的话放 `dialogue/festival.dialogue`。
- 对话里要用到的游戏状态（忆等级、季节、是否点过某盏灯）通过 `Residents` 暴露给 Dialogue Manager，对话文件不直接访问各个玩法系统（`core` 里的 `GameClock`、`Weather`、`EventBus` 的请求函数可以直接用）。
- 对话框界面自己做，放在 `features/ui/`，不用插件自带的示例气泡。说话人的名字对得上居民时显示头像（`UiKit.face(sheet, mood)`，图在 `art/characters/<id>_face.png`，横着三格表情，由 `tools/portraits.py` 画，决策 033）；台词后面的 `[#happy]`、`[#sad]` 决定用哪一格。
- 写台词的规矩见决策 034：闲聊话题用 `Residents.topic` 抽，处境用 `Residents.at`、`time_is`、`away`、`owes_thanks`、`nth`、`knows` 判断。
- 对话框开着时新来的对话请求会排在后面播（决策 031）。名册和忆簿是 `features/ui/residents_panel.gd`（`ResidentsPanel`），公告栏是 `board_panel.gd`，点灯是 `lamp_panel.gd`，菜谱是 `cook_panel.gd`；界面只读各 autoload 的状态，改状态只通过它们的方法。
- 剧情进度用 `GameState` 里的标记表示，标记名集中列在一个文件里。

## 12. 第三方库

### 已接入

| 库 | 版本 | 用途 | 许可 | 位置 |
|---|---|---|---|---|
| [GUT](https://github.com/bitwes/Gut) | 9.7.1（对应 Godot 4.7） | 单元测试 | MIT | `addons/gut` |
| [Dialogue Manager](https://github.com/nathanhoad/godot_dialogue_manager) | 4.2.0（对应 Godot 4.7） | 分支对话、条件、变量 | MIT | `addons/dialogue_manager` |

升级方法：下载新版本，整个替换对应的 `addons/` 子目录，跑一遍测试。

### 评估过、暂不接入

| 库 | 用途 | 结论 |
|---|---|---|
| Dialogic | 对话 | 功能更重，带整套界面和时间线编辑器；本项目界面自己画，用不上，选了更轻的 Dialogue Manager |
| LimboAI、Beehave | 行为树和状态机 | M5 评估过：忘形的行为是一条固定的步骤，自己写的状态机就够，不接（决策 051） |
| Godot State Charts | 状态机 | 玩家和居民的状态不复杂，先用简单写法 |
| Phantom Camera | 相机 | 自带的 `Camera2D` 够用 |
| gdtoolkit（gdlint、gdformat） | 代码检查和格式化 | 有用但不急；接入前要确认它支持 4.7 的语法 |
| 存档类插件 | 存档 | 存档格式和迁移要完全可控，自己写 |

原则是能少则少：每个库都是以后升级引擎时的一个风险点。只在“自己写要花很多时间，而且库的质量明显更好”时才引入。

### 关于 Godot 开发 skill

本机没有安装 Godot 相关的 skill。网上有社区写的（例如 GD-Agentic-Skills、awesome-gamedev-agent-skills），我读了其中的要点，但没有安装：skill 文件会在以后的每次会话里被当作指令执行，未经审查的第三方指令不适合直接装进来。

取而代之的是把 Godot 官方文档（项目组织、GDScript 风格指南、静态类型）和这些社区要点里通用的部分，整理成了本项目自己的规则：

- `AGENTS.md`：每次会话都会读的项目说明。
- `.cursor/rules/gdscript.mdc`：编辑 `.gd` 文件时生效的编码规范。

## 灯油、黑暗和饰品（决策 055）

- 灯油 `Mine.oil` 和戴着的饰品 `Mine.equipped` 都记在 `Mine` 里、进存档，没有新的 autoload。规则都是 `Mine` 的函数：`burn`（全黑的层里烧油）、`snuff`（被吃掉、吹掉一口）、`refuel`、`light_radius`、`bonus(effect)`（戴着的饰品里这种效果加起来多少）、`toggle_accessory`、`trial_running / finish_trial / restart_trial`（岚之影的考验）。
- 一层黑不黑是 `MineLayerDef.dark` → `MineFloor.dark`；地图每帧把灯照多远写进 `MineFloor.light`，怕光的忘形（`MonsterDef.shy`）自己看。画面上的黑是 `GameMap.forced_tint()`：地图返回一个不透明的颜色，`Game._update_tint` 就不按钟点算、直接用它；光是地图里跟着人的一盏 `PointLight2D`。
- 拿着东西对着空处按使用键：`Game` 先看是不是饰品（戴上或摘下），再问地图的 `use_item(item)`（井里用来添灯油），都不是才轮到吃东西。
- 饰品的定义在 `data/accessories.json`（`AccessoryDef`），物品种类是 `accessory`。效果名固定在 `AccessoryDef.EFFECTS`，用的地方各自去问 `Mine.bonus`：`mine_map`（护甲、蹚水、武器加成、翻滚后的无敌写给 `Player.roll_grace`）、`Mine`（省油、灯照远、打倒回血）。
- 商店的一行可以除了钱还要材料（`ShopEntry.materials`）：`Shop.has_materials`，`affordable_entry / buy_entry` 一起查、一起扣。
- 新首领照旧是 `MineMonster` 的子类：`MineTroupe`、`MineShade`。新开关：`MonsterDef.eat_light`（撞到不扣生命、吃灯油）、`echo`（照着人几秒前的路走）、`shy`；`MineShot.snuff`（吹灯的风）；`MineMonster.skin()`（同一只换几副样子）。
