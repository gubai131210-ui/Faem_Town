# 架构

> 这份文档规定代码怎么组织。写新功能前先看这里；要偏离时，先在 [决策记录](决策记录.md) 里写明原因。
> 玩法内容见 [设计文档](设计文档.md)，进度见 [进度](进度.md)。

## 1. 技术栈

| 项 | 选择 |
|---|---|
| 引擎 | Godot 4.7.2，GL Compatibility 渲染 |
| 语言 | GDScript，全部写静态类型 |
| 画面 | 基础分辨率 384×216，整数倍放大，纹理不过滤 |
| 角色美术 | Blender 5.3 脚本建模和渲染，输出像素序列帧 |
| 其他美术 | 代码逐像素绘制 |
| 测试 | GUT |
| 对话 | Dialogue Manager |

## 2. 核心原则

1. **状态和画面分开。** 游戏状态（田里种了什么、背包里有什么、今天第几天）放在纯数据对象里，不依赖任何节点。节点只负责把状态画出来和接收输入。这样玩家不在农场时作物照样生长，存档就是把状态对象写出去。
2. **内容放在数据表里。** 加一种作物、一条鱼、一个居民，只改 `data/` 下的表，不改代码。
3. **向下调用，向上发信号。** 父节点可以直接调子节点的方法；子节点不调父节点，只发信号。
4. **功能之间不直接引用。** 钓鱼不 `preload` 种田的脚本。需要联动时走全局系统或 `EventBus`。
5. **全局单例要少。** 只有“全局唯一、跨场景存在、自己管理自己数据”的系统才做成 autoload；纯工具函数用 `class_name` 加静态方法。
6. **第三方代码只放 `addons/`。** 不改插件源码；要定制就在自己的目录里包一层。

## 3. 目录结构

这是目标结构，M0 会把 demo 的代码迁进来。

```
farm-town/
  addons/              第三方插件，不改动
  core/                全局系统（autoload）和基础工具，不含具体玩法
  data/                内容表：作物、鱼、物品、居民、节气……
  dialogue/            对话文件，每个居民一个
  features/            每个玩法一个目录，脚本、场景、专属素材放在一起
    player/
    farming/
    fishing/
    animals/
    mine/
    npc/
    lamps/             灯、供品、主线进度
    ui/
  maps/                每个区域一个场景
  art/                 生成出来的图片（Blender 输出等）
  art_gen/             代码画图的脚本（地形、物件、图标）
  tests/               GUT 测试
  tools/               Blender 脚本等编辑期工具，带 .gdignore
docs/                  文档（在 Godot 项目目录之外）
```

规则：

- 文件和目录一律 `snake_case`，节点名 `PascalCase`。
- 素材跟着用它的功能走；多个功能共用的才放 `art/`。
- `features/a/` 不引用 `features/b/` 里的文件。

## 4. 分层

```
maps / features/ui      场景和界面：组装节点，显示状态，接收输入
        ↓ 调用
features/*              玩法逻辑：每个玩法自己的状态对象和规则
        ↓ 调用
core                    全局系统：时间、天气、存档、数据库、事件
        ↓ 调用
data / addons           内容表和第三方库
```

下层不知道上层的存在。上层要知道下层发生了什么，就连接下层的信号。

## 5. 全局系统

计划中的 autoload，按加载顺序：

| 名称 | 职责 | 引入时间 |
|---|---|---|
| `Database` | 启动时读入并校验 `data/` 下所有表，提供按 id 查询 | M0 |
| `EventBus` | 跨功能的全局信号，数量要少，每个都写注释 | M0 |
| `GameClock` | 时间、日期、季节、节气；发出“新的一天”“节气变化” | M0（节气在 M1） |
| `GameState` | 玩家的全局数据：背包、金钱、体力、剧情标记 | M0 |
| `SaveSystem` | 存读档，调度各系统的存取 | M0 |
| `SceneRouter` | 区域切换、转场、出生点 | M0 |
| `Audio` | 音效和音乐 | M0（迁移现有的） |
| `Weather` | 天气生成和查询 | M1 |
| `DialogueManager` | 对话运行时（插件提供） | 已接入 |

约定：

- autoload 之间只能依赖排在自己前面的。
- autoload 不持有任何场景里的节点引用。

### 每日结算

睡觉时 `GameClock` 推进一天并发出 `day_started`。各系统按固定顺序结算：天气 → 作物 → 动物 → 加工设备 → 居民日程 → 出货结账 → 自动存档。顺序写在 `GameClock` 里，不靠信号连接的先后。

## 6. 数据表

- 格式是 JSON，放在 `data/`，一类内容一个文件，例如 `data/crops.json`。
- 每条内容有一个 `id`：小写英文加下划线，例如 `white_radish`。**id 一旦进入存档就不能改名。** 显示名用中文，放在 `name` 字段。
- `Database` 读入时把每条数据转成带类型的定义对象（`CropDef`、`ItemDef`……），代码里不直接摸字典。
- 表之间的引用（作物的种子 id、居民喜欢的物品 id）在启动时校验，测试里也校验一遍。错了直接报错，不带病运行。

选 JSON 而不是 Godot 的 `.tres`，是因为内容量大、多数由脚本和 AI 批量生成，纯文本表更容易批量写、对比和检查。

## 7. 存档

- 位置 `user://saves/slot_N.json`，三个档位。
- 每个有状态的系统实现两个方法：`save_data() -> Dictionary` 和 `load_data(data: Dictionary) -> void`。`SaveSystem` 只负责收集、写盘和分发。
- 存档带 `version` 字段。结构变化时加一个迁移函数，把旧版本逐级升到新版本。
- 写盘先写临时文件，成功后再替换，并保留上一份作备份。读档失败时不覆盖原文件。
- 只在睡觉时自动存档，所以不需要保存“一天中途”的状态。

## 8. 场景与节点

- 可复用的东西做成独立场景（`.tscn`），根节点挂一个同名脚本。
- 地图、界面布局这类“摆放”的内容用场景文件；demo 里全部用代码建节点的做法只保留给程序生成的内容（矿井楼层、代码画的贴图）。
- 节点引用用 `@onready` 和 `%唯一名`，不在 `_process` 里查找节点。
- 行为复杂的对象用状态机。玩家先用枚举加 `match` 的简单状态机；怪物 AI 到 M5 再决定自己写还是引入库。

## 9. 美术管线

| 内容 | 来源 | 输出 |
|---|---|---|
| 人形角色 | `tools/` 下的 Blender 脚本，一套骨架和动作，按配置换发型、服装、配色 | `art/characters/*.png` |
| 动物、怪物 | 同上，各自的骨架 | `art/creatures/*.png` |
| 对话头像 | 同一个模型的近景渲染 | `art/portraits/*.png` |
| 地形、建筑、植物、图标 | `art_gen/` 下的代码绘制 | 运行时生成并缓存 |

- 序列帧统一 48×48 一格，脚底在第 40 行，行列含义写在同名的 `.json` 里，代码不硬编码帧数。
- Blender 输出的图片作为正常的 Godot 资源导入，不在运行时从磁盘读文件。
- 调色板只有一份，Blender 脚本和 Godot 代码都从它读。

## 10. 对话与剧情

- 每个居民一个 `dialogue/<id>.dialogue` 文件，按“日常、雾天、各级记忆、节日”分段。
- 对话里要用到的游戏状态（忆等级、季节、是否点过某盏灯）通过一个专门的对象暴露给 Dialogue Manager，对话文件不直接访问各个系统。
- 对话框界面自己做，放在 `features/ui/`，不用插件自带的示例气泡。
- 剧情进度用 `GameState` 里的标记表示，标记名集中列在一个文件里。

## 11. 测试与检查

| 手段 | 测什么 | 怎么跑 |
|---|---|---|
| GUT 单元测试 | 纯逻辑：历法、作物生长、存档往返、数据表引用是否有效 | 见下方命令 |
| 自动流程截图 | 游戏能启动、主要流程不报错、画面没坏 | `-- --shots` |
| 你的试玩 | 手感、动作、声音、好不好玩 | 每个里程碑 |

规则：

- 新的逻辑代码要有对应的单元测试；改 bug 先写一个能复现的测试。
- 每个里程碑扩充自动流程脚本，覆盖新玩法。
- 报告完成之前，测试和自动流程都要跑过。

### 常用命令

在 `farm-town/` 目录下，`$g` 是 Godot 的 console 版可执行文件：

```powershell
# 导入资源（新拉下来的项目要跑两次，第一次插件还没注册，对话文件不会被导入）
& $g --headless --path . --import

# 跑全部单元测试
& $g --headless --path . -s addons/gut/gut_cmdln.gd -gexit

# 自动跑流程并截图到 _preview/
& $g --path . -- --shots

# 重新生成角色序列帧
& "D:\Blender 5.3\blender.exe" --background --python tools\farmer.py
```

## 12. 第三方库

### 已接入

| 库 | 版本 | 用途 | 许可 | 位置 |
|---|---|---|---|---|
| [GUT](https://github.com/bitwes/Gut) | 9.7.1（对应 Godot 4.7） | 单元测试 | MIT | `addons/gut` |
| [Dialogue Manager](https://github.com/nathanhoad/godot_dialogue_manager) | 4.2.0（对应 Godot 4.7） | 分支对话、条件、变量 | MIT | `addons/dialogue_manager` |

升级方法：下载新版本，整个替换对应的 `addons/` 子目录，跑一遍测试。

### 评估过、暂不接入

| 库 | 用途 | 结论 |
|---|---|---|
| Dialogic | 对话 | 功能更重，带整套界面和时间线编辑器；本项目界面自己画，用不上，选了更轻的 Dialogue Manager |
| LimboAI、Beehave | 行为树和状态机 | 只有矿井怪物需要，M5 再评估；LimboAI 是二进制扩展，要确认 4.7 版本 |
| Godot State Charts | 状态机 | 玩家和居民的状态不复杂，先用简单写法 |
| Phantom Camera | 相机 | 自带的 `Camera2D` 够用 |
| gdtoolkit（gdlint、gdformat） | 代码检查和格式化 | 有用但不急；接入前要确认它支持 4.7 的语法 |
| 存档类插件 | 存档 | 存档格式和迁移要完全可控，自己写 |

原则是能少则少：每个库都是以后升级引擎时的一个风险点。只在“自己写要花很多时间，而且库的质量明显更好”时才引入。

### 关于 Godot 开发 skill

本机没有安装 Godot 相关的 skill。网上有社区写的（例如 GD-Agentic-Skills、awesome-gamedev-agent-skills），我读了其中的要点，但没有安装：skill 文件会在以后的每次会话里被当作指令执行，未经审查的第三方指令不适合直接装进来。

取而代之的是把 Godot 官方文档（项目组织、GDScript 风格指南、静态类型）和这些社区要点里通用的部分，整理成了本项目自己的规则：

- `AGENTS.md`：每次会话都会读的项目说明。
- `.cursor/rules/gdscript.mdc`：编辑 `.gd` 文件时生效的编码规范。
